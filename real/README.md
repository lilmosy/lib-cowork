# real — 실제 구현

사서용 화면(`app.py`)과 실행 CLI(`run.py`), 그리고 둘이 함께 쓰는 파이프라인(`src/`)입니다.
프로젝트 소개는 [../README.md](../README.md), 설계 근거는 [../docs/design.md](../docs/design.md)에 있습니다.

이 폴더를 프로젝트 루트로 보고 여기서 실행합니다.

---

## 받아서 돌리기

### 1. 설치

```bash
pip install -r requirements.txt
```

### 2. 데이터

**`data/` 안의 데이터는 저장소에 없다** (크롤 산출물과 출판사 저작물이라 커밋하지 않는다). **데이터는 요청 시 제공합니다.** 받은 파일은 `data/`에 넣는다:

```
data/sogang_db_final.db    본교 장서 884,577건 (SQLite, 1.3GB)
data/union_db.json         종합서지 306행 (표본 도서분)
data/aladin_cache.json     책소개 캐시 — 없으면 알라딘 API로 다시 받는다(느릴 뿐 동작함)
```

골든셋은 실제 구현과 분리해 `../experiment/data/scenarios/`에 둔다. **책소개 캐시는 출판사
저작물이라 저장소에 두지 않는다.**

### 3. API 키

`.env.example`을 복사해 `.env`를 만들고 키를 넣는다. 상위 폴더의 `.env`도 자동으로 찾는다.

```bash
cp .env.example .env
```

| 키 | 쓰는 곳 | 발급 |
|---|---|---|
| `OPENAI_API_KEY` | 기본 판단 모델(gpt-5.6-terra) | platform.openai.com |
| `ANTHROPIC_API_KEY` | Claude 비교 시에만 | console.anthropic.com |
| `ALADIN_TTB_KEY` | 책소개 | 알라딘 → 오픈API → TTB 인증키 (무료) |

`ALADIN_TTB_KEY`가 없어도 파이프라인은 돈다 — 책소개 없이 판단할 뿐이다.

### 4. 실행

```bash
python run.py mybook.json            # 책 한 권 분류해보기
streamlit run app.py                 # 사서용 데모 화면

# 비교실험이 필요할 때만
cd ../experiment
python evaluate.py --label=myrun --runs=3
```

## 알아야 할 값

흐름을 정하는 건 **LLM이 매기는 점수 하나**와 **코드가 자르는 선 둘**입니다.

### `shelf_fit` — LLM이 매기는 점수 (0.0 ~ 1.0)

"이 신규 도서가 **본교 그 번호대 서가에 꽂혀도 어울리나**"입니다. 후보 번호마다 하나씩 붙습니다.

```
1.0  그 서가 책들과 사실상 같은 성격이다
0.7  주제는 맞는데 성격(전문서/교양서, 이론/실용)이 조금 다르다
0.4  큰 갈래는 겹치지만 초점이 다르다
0.0  전혀 다른 자리다
```

⚠️ **계산값이 아닙니다.** 임베딩 유사도 같은 수식이 없어요. 후보 번호대의 본교 책
40권(제목 + 주제명·요약 등)을 LLM이 읽고 판단해 뱉는 숫자입니다. **그래서 실행마다 흔들립니다.**

⚠️ **확신도가 아닙니다.** "이 답이 맞을 확률"이 아니라 "이 자리에 어울리나"입니다.

현재 운영 프롬프트는 비교실험에서 선택한 **two-axis** 방식입니다. 먼저
`주제·관점 적합도`와 `자료 성격·용도 적합도`를 각각 매기고, 두 값의 산술평균을
`shelf_fit`으로 냅니다. 구체 지시는 `prompts/systemprompt_shelf_fit.txt`, 출력 계약은
`src/schema.py::ShelfFitAssessment`가 담당합니다.

### `THRESHOLD_2` · `GAP_MIN` — 자르는 선 두 개

```
THRESHOLD_2 = 0.80   1순위 점수가 이 값 미만 → 사서
GAP_MIN     = 0.15   1·2위 격차가 이 값 미만 → 사서
```

**두 조건을 다 넘어야 「수렴」이다.** 각자 다른 실패를 막는다:

- **점수**는 *어떤 서가도 확신 못 하는 책*을 막는다. #11 부린왕자는 격차가 0.16까지
  벌어진 회차가 있었지만 1위 점수가 0.71이라 여기서 걸린다.
- **격차**는 *그럴듯한 1위 뒤에 경합이 숨은 책*을 막는다. #9 서점은 1위가 0.90~0.93인데
  사서 두 사람이 갈렸다 — 점수 문턱만 있었다면 틀린 채 확정됐을 건을 격차 0.05~0.10이
  걸러냈다. **1위 점수 하나로는 "사람도 갈린 건"을 못 잡는다**(갈린 책은 두 서가가 다 높다).

이 두 조건은 **두 곳에서 같은 함수로** 쓰인다(`decide.decide()`). 별도 문턱은 없다.

```
2단계 게이트   082+종합서지까지로 이미 수렴이면 → 키워드를 안 돌고 종결
              LIBCOPILOT_STAGE2_GATE (기본 on) · 평가 회차는 자동으로 끈다
최종 판정      3단계까지 간 뒤 같은 두 조건으로 수렴 여부를 판정 → 화면 문구가 갈린다
```

스위치는 게이트 하나뿐이다(끄면 실험용으로 전 건이 3단계까지 간다). 확정은 수렴이든
아니든 **사서가 버튼으로** 한다 — 수렴은 클릭 한 번, 갈림은 골라야 확정된다.
(구 AUTO_CONFIRM 스위치는 "사서 없이 확정"할 경로가 앱에 없어 2026-09-02 제거했다.)

값 근거는 2026-08-25 회차(two_axis, 표본 × 3회)를 다시 읽어 정했다 — 여유는 격차 쪽
0.31(통과 최소) 대 0.10(저지 최대), 점수 쪽 0.86 대 0.82다.
⚠️ **같은 표본에 되적용한 in-sample 값이라 잠정이다.** 기준선 회차에서 재확인한다.

> 1단계 게이트(`THRESHOLD_1`)는 2026-09-02에 없앴다. 값이 틀린 게 아니라 **존재하지
> 않는다** — 082가 정답인 유일한 케이스(#8, 0.70~0.80)보다 082가 오답인 #7(0.85~0.90)과
> 사람이 갈린 #9(0.90~0.93)의 점수가 높아, #8을 통과시키는 값은 반드시 #7·#9도
> 통과시킨다. 서가 하나만 놓고 본 점수는 082의 정오와 상관이 약하다.

### 튜닝하는 순서

```
① 프롬프트를 고친다     prompts/systemprompt_shelf_fit.txt → 점수 분포가 움직임. 표본 재실행 필요
② 축·평균 정의를 고친다  운영 프롬프트 + schema 설명  → 점수 분포가 통째로 움직임. 표본 재실행 필요
③ 서가 표본을 바꾼다     config.SHELF_SAMPLE(40권)    → 점수의 근거가 바뀜. 표본 재실행 필요
                        config.MAX_UNION_CANDIDATES(3위)
④ 자르는 선을 옮긴다     config.THRESHOLD_2 · GAP_MIN  → 재실행 불필요. 저장된 .json만으로 쓸어볼 수 있음
```

**④를 마지막에 하세요.** ①②③을 고치면 점수 분포가 움직여서 임계값을 어차피 다시 찾아야 합니다.
값은 환경변수로도 바뀝니다:

```bash
LIBCOPILOT_THRESHOLD_2=0.75 python run.py mybook.json
```

## 프롬프트는 파일에 있습니다 — `prompts/`

시스템 프롬프트를 코드 밖으로 뺐습니다. **고치려고 파이썬 파일을 열 필요가 없습니다.**

```
prompts/systemprompt_shelf_fit.txt  독립 fit — 책 1권 × 서가 1곳. 후보마다 같은 지문을 다시 쓴다
prompts/systemprompt_keyword.txt    책 정보만 보고 검색어를 만드는 호출
```

지문이 **둘뿐**입니다. fit 지문 한 줄을 고치면 모든 후보의 점수가 같은 방식으로 움직입니다 —
그게 이 구조의 요점입니다(예전엔 1차·2차 지문이 한 쌍이라 한쪽만 고치면 앞뒤가 어긋났습니다).
**파일명은 ASCII로 둡니다** — 한글 파일명은 OS마다 정규화가 갈려 클론했을 때 "파일 없음"이 납니다.

비교실험에 쓴 다섯 버전은 `../experiment/prompts/`에 보관합니다. 실험기는 환경변수로
그중 하나를 운영 파이프라인에 연결합니다:

```bash
cd ../experiment
LIBCOPILOT_PROMPT_SYSTEMPROMPT_SHELF_FIT=prompts/exp_shelf_fit_two_axis.txt \
  python evaluate.py --label=two_axis
```

어떤 파일로 돌렸는지와 지문 해시가 회차 json의 `setup`에 남으므로, 나중에 그 회차를 재현할 수 있습니다.

운영 `systemprompt_shelf_fit.txt`는 두 축과 평균 방식을 본문에서 직접 정의합니다.
`{SHELF_FIT_RUBRIC}`은 비교실험의 기준선 파일에서만 사용하는 호환용 자리입니다.

## 실행 파일

| | 무엇 | 산출물 |
|---|---|---|
| **`run.py`** | 책 한 권을 분류하고 결과·근거를 보여준다 | 터미널 |
| **`app.py`** | 사서가 쓰는 데모 화면. 결과 + 근거 + 확정/변경 | `runs/decisions_*.jsonl` |

두 파일 모두 같은 파이프라인(`pipeline.classify_book`)을 부릅니다. `real/` 내부 파일만으로
직접 입력 도서를 처리하며, `experiment/`를 import하거나 골든 정답을 읽지 않습니다.

평가 CLI와 프롬프트 작업창은 `../experiment/`에 있습니다.

## 디렉터리

`real/` 자체가 데모 구현의 프로젝트 루트입니다.

```text
real/
├── README.md
├── app.py · run.py · requirements.txt · .env.example
├── src/                    실제 파이프라인 라이브러리
├── prompts/                최종 운영 프롬프트 2개
├── data/                   ❌ 본교 DB·종합서지·책소개 캐시
├── runs/                   데모에서 사서가 확정한 기록
└── tools/crawler/          DB 구축용 오프라인 도구
```

비교실험의 골든셋·다섯 프롬프트·평가 스크립트·결과는 형제 폴더 `../experiment/`에만
있습니다. `real/` 실행에는 필요하지 않습니다.

**읽는 순서** — `pipeline.py`(흐름) → `schema.py`(주고받는 것) → `prompts/`(지문) →
궁금한 한 단계만 아래 파일로.
파일이 **왜 이렇게 나뉘었는지**는 [../docs/design.md §6](../docs/design.md)에 있습니다.

## 손대기 전에

코드를 고칠 거면 **[../docs/design.md §8 규약](../docs/design.md)** 을 먼저 읽을 것.

⚠️ 특히 **크롤 데이터(`sogang_db_final.db`·`union_db.json`)는 커밋하지 않는다.** 실수로 올리면 되돌리기 번거롭다.

승계 검색용 인덱스는 배포 DB에 이미 들어 있다. 직접 만들 일이 생기면 SQL은
`src/sogang_db.py`의 `find_inheritance()` 주석에 있다.
